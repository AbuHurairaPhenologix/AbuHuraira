# 📌 Overview

EchoSense AI turns an ordinary audio file into an explorable, searchable, synchronized analysis:

- 🎙️ **What was said** — Whisper transcription with word-accurate timestamps and language detection
- 🧑‍🤝‍🧑 **Who said it** — speaker clustering from WavLM voice embeddings, speaking time, share and turns
- 🔊 **What else happened** — AudioSet sound events (speech, music, applause, siren, alarm, door, …)
- 🎭 **How it sounded** — emotion estimates plus measured prosody (pitch, variability, loudness, rate)
- 🚨 **What was unusual** — Isolation-Forest acoustic anomaly detection with per-feature explanations
- 📈 **Where it is heading** — next-interval forecasts of energy, conversation activity, anomaly likelihood and engagement
- 🔎 **Where was X discussed?** — local semantic search over transcript and sound events
- 🌐 **Where are the sounds?** — an interactive Three.js world with HRTF spatial playback
- 📝 **What was it about?** — a grounded summary with topics and quoted key moments

> **Honesty by design.** Speakers are anonymous clusters, emotions are labelled *model estimates*, forecasts are always shown next to a naive baseline, the summary contains only computed facts, and the spatial world says plainly that a mono file has no direction information.

# 🖼️ System Architecture

```mermaid
flowchart LR
    U["🧑 Browser<br/>React + TypeScript"] -->|"upload WAV / MP3 / FLAC"| API["⚡ FastAPI"]
    API --> DB[("🗄️ SQLite<br/>results")]
    API -->|"background thread"| P["🧠 Analysis pipeline"]
    P --> A["🎛️ Audio layer<br/>librosa · torchaudio · soundfile"]
    P --> M["🤗 Pretrained models<br/>Whisper · AST · WavLM · wav2vec2 · MiniLM"]
    P --> AN["📊 Analytics<br/>Isolation Forest · AR(1) · vector search · summary"]
    P --> DB
    P --> FS[("📁 Artifacts<br/>spectrogram · features · .npy index")]
    API --> FS
    U -->|"poll status · fetch results · search"| API
    U --> V["🎨 WaveSurfer · Recharts · Three.js · Web Audio"]
```

Everything runs in **one Python process and one Vite dev server**. There is no Docker, Redis, message queue or vector database — models are loaded lazily once, analysis runs in a FastAPI background thread, and the vector index is a NumPy array.

# 🧠 AI Pipeline

```mermaid
flowchart TD
    UP["📤 Upload<br/>original stored unchanged"] --> PRE["🎛️ Preprocessing<br/>16 kHz mono · normalise · silence · spectrogram"]
    PRE --> FE["🧮 Feature extraction<br/>RMS · ZCR · spectral shape · onsets · MFCC"]
    FE --> SED["🔊 Sound events<br/>AST on 2 s windows"]
    SED -->|"speech probability<br/>selects speech regions"| ASR["🎙️ Whisper<br/>word timestamps → segments"]
    ASR --> SPK["🧑‍🤝‍🧑 Speakers<br/>WavLM x-vectors → clustering"]
    SPK --> EMO["🎭 Emotion + prosody"]
    FE --> ANO["🚨 Isolation Forest<br/>absolute + novelty features"]
    ASR --> PRED["📈 Interval metrics → AR(1)"]
    ANO --> PRED
    ASR --> IDX["🔎 MiniLM index"]
    SED --> IDX
    IDX --> SUM["📝 Topics · highlights · summary"]
    SPK --> SUM
    ANO --> SUM
    SUM --> DB[("🗄️ SQLite + artifacts")]
```

| Stage | Model / method | Output |
|---|---|---|
| Transcription | [`openai/whisper-base`](https://huggingface.co/openai/whisper-base) | segments, word-level timing, language |
| Sound events | [`MIT/ast-finetuned-audioset-10-10-0.4593`](https://huggingface.co/MIT/ast-finetuned-audioset-10-10-0.4593) | 527 AudioSet classes → 13 dashboard categories |
| Speakers | [`microsoft/wavlm-base-plus-sv`](https://huggingface.co/microsoft/wavlm-base-plus-sv) | anonymous speaker clusters, time, share, turns |
| Emotion | [`superb/wav2vec2-base-superb-er`](https://huggingface.co/superb/wav2vec2-base-superb-er) | neutral / happy / angry / sad + confidence |
| Embeddings | [`sentence-transformers/all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) | 384-d vectors for search and topics |
| Anomalies | scikit-learn `IsolationForest` | window scores, regions, top deviating features |
| Forecasts | AR(1), NumPy | next-interval value, trend, MAE vs baseline |

**Why sound events run before transcription.** The AST speech probability decides which activity regions Whisper sees. On the first version Whisper was fed music + speech together and its first segment started at 0.0 s instead of 8.2 s; routing only speech regions brought the mean start offset to **0.06 s** and removes hallucinated text over music and silence.

**Speaker clustering.** Each segment's WavLM x-vector is clustered agglomeratively (cosine, average linkage). The speaker count is chosen by silhouette score, and a split is only accepted when every pair of cluster centroids is below the model's recommended **0.86** same-speaker cosine threshold — a unit test proved silhouette alone could split a single voice into two.

# 🎛️ Audio Analytics

| Step | Implementation |
|---|---|
| Decode | `soundfile` (libsndfile ≥ 1.1: WAV, FLAC, MP3) |
| Resample | `torchaudio.functional.resample` → 16 kHz |
| Mono / normalise | channel mean, peak normalisation to −1 dBFS |
| Silence detection | `librosa.effects.split` at −35 dB re peak, gaps < 0.4 s bridged |
| Segmentation | activity intervals packed into ≤ 28 s chunks for Whisper |
| Visuals | 2,400-bucket waveform peaks; 96-band log-Mel spectrogram quantised to uint8 |
| Window features | n_fft 1024, hop 16 ms, aggregated to 1 s windows / 0.5 s hop: RMS dB (mean, std), ZCR, spectral centroid / rolloff / bandwidth / flatness, onset strength (mean, peak), MFCC 1-13 |

# 🚨 Anomaly Detection

<p align="center">
  <img src="docs/screenshots/anomaly-detection.png" width="85%" alt="Isolation-Forest anomaly score over time with threshold and the flagged glass shatter, plus the explanation table" />
</p>

**Model.** An Isolation Forest (300 trees) is fit on the recording's own windows. The score shown is the original Isolation-Forest anomaly score `s(x) = 2^(−E[h(x)]/c(n))` ∈ [0, 1]: ordinary windows sit near 0.4–0.5, windows that random splits isolate quickly score higher.

**Features (15 per window).**

| Absolute (10) | Contextual novelty (5) |
|---|---|
| RMS dB, RMS std, ZCR, spectral centroid, rolloff, flatness, onset peak, MFCC 1-3 | deviation of RMS, centroid, flatness, onset peak and MFCC 2 from the **median of the previous 10 s**, scaled by that context's inter-decile range |

Novelty is what makes *sudden* events stand out rather than merely rare-but-steady sounds. Measured on the demo:

| Feature set | Glass-shatter score | Rank |
|---|---|---|
| 22 absolute features only | 0.605 | 3rd — below the siren and the music intro |
| **10 absolute + 5 novelty (one-sided energy)** | **0.739** | **1st — the only region above threshold** |

**Threshold.** Recording-relative and robust: `median + 6 · MAD` of the scores, never below 0.6. Consecutive flagged windows merge into one region; each region reports its peak, score, overlapping sound events and the four most deviating features (e.g. `onset_peak_novelty +3.19 · zcr +2.85 · spectral_centroid_novelty +2.28`).

# 📈 Predictive Analytics

<p align="center">
  <img src="docs/screenshots/predictive-analytics.png" width="85%" alt="Predictive analytics: current vs next-interval values for four metrics and the walk-forward backtest chart" />
</p>

The recording is split into ~24 intervals (5–60 s). Four 0–100 metrics are **measured** per interval:

| Metric | Definition |
|---|---|
| Audio energy | mean window loudness, scaled to the recording's 5th–95th percentile dB range |
| Conversation activity | % of the interval covered by transcribed speech |
| Anomaly likelihood | mean anomaly score, scaled between the recording median and the threshold |
| Engagement | mean of conversation activity, speaker-turn rate (scaled) and energy |

**Model:** a mean-reverting AR(1) per metric — `next = μ + φ · (current − μ)` — fit by least squares on the intervals seen so far. It is fully explainable (two numbers) and its accuracy is measured with a **walk-forward backtest** (each interval predicted only from earlier ones) against the naive *persistence* baseline ("same as last interval"):

| Metric | Walk-forward MAE | Persistence MAE | μ | φ |
|---|---|---|---|---|
| Audio energy | **11.9** | 13.6 | 58.8 | 0.15 |
| Conversation activity | **28.2** | 32.9 | 65.9 | 0.00 |
| Anomaly likelihood | **9.5** | 10.3 | 10.1 | 0.00 |
| Engagement | **20.5** | 27.4 | 53.1 | 0.00 |

A ridge model with three lags and cross-metric terms was tried first and **lost to persistence on all four metrics** (it overfits ~23 points), so it was replaced. With fewer than 7 intervals the API returns a labelled persistence forecast and claims no accuracy.

# 🔎 Semantic Search

<p align="center">
  <img src="docs/screenshots/semantic-search-events.png" width="85%" alt="Semantic search for 'Where did the audience applaud?' returning the applause sound events with timestamps and similarity scores" />
</p>

- Index = every transcript segment + a context passage (segment with neighbours) + one natural-language description per detected sound event, embedded with MiniLM and stored as `search_index.npy`.
- Query → embedding → cosine similarity with NumPy → results de-duplicated by time and returned with **timestamp, text, speaker and similarity score**.
- Because events are indexed too, *"Where did the audience applaud?"* returns the applause at **00:18** and **02:50**, while *"Where did they discuss artificial intelligence?"* returns transcript lines. Clicking any result plays the recording from that moment.

# 🌐 Spatial Audio World

<p align="center">
  <img src="docs/screenshots/spatial-scene.png" width="85%" alt="Three.js spatial audio world: speakers in front of the listener, music, applause, siren, alarm and the anomaly around, Speaker 2 playing" />

- Speakers are arranged on the front arc, other sound sources and anomalies around the sides and back; sphere size reflects total activity time.
- **Drag** to rotate, **scroll** to zoom, **click** a source (or a row in the side panel) to hear its most representative clip.
- Playback uses a Web Audio **`PannerNode` with the HRTF model** at the object's 3D position; the listener's orientation follows the camera, so a source on the left of your view is heard on the left (use headphones).

# 📝 AI Audio Summary

<p align="center">
  <img src="docs/screenshots/ai-summary.png" width="60%" alt="Grounded AI recording summary with topics, speaker statistics, event times, anomaly time and quoted key moments" />
</p>

The summary is **grounded and extractive** — no free-text generation, so nothing can be hallucinated:

- **Topics:** KeyBERT-style — 1-2-word phrases taken from the raw transcript word sequence (no stop-words inside, so no fake phrases like "talk product"), ranked by embedding similarity to the whole transcript and diversified with Maximal Marginal Relevance → *Audio Analytics, AI Conference, Product Planning, Forecast Conversation, Event Detection*.
- **Facts:** speaker count and the most active speaker, the most active 3-interval span, the first time of each non-speech event, anomaly count and times, dominant estimated tone.
- **Key moments:** the transcript segments closest to the transcript centroid, quoted verbatim with timestamps.

# ⚙️ Setup

**Prerequisites:** Python 3.10–3.12, Node.js 20+, ~3 GB free disk for the model cache. A GPU is used automatically if PyTorch sees one; CPU works fine.

```bash
cd EchoSense-AI

# Backend
python -m venv .venv
.venv\Scripts\activate                     # macOS / Linux: source .venv/bin/activate
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu   # or the CUDA build
pip install -r requirements.txt

# Frontend
cd frontend
npm install
```

The five models (~2.3 GB in the Hugging Face cache) are downloaded from Hugging Face on the first analysis and cached afterwards. No API keys or gated models are required.

# ⚠️ Limitations

- **Speaker analysis is clustering, not identification** — one speaker per transcript segment, overlapping speech is not separated, and very short segments inherit the previous speaker. A full diarization model (e.g. pyannote) would handle overlaps but requires a gated model and an access token, so it was deliberately not used.
- **Emotion labels are model estimates** from a 4-class model trained on acted English speech (IEMOCAP); they are not psychological facts. The Calm / Moderate / Animated arousal label is a heuristic relative to the same recording.
- **Sound-event recall depends on the sound.** On the demo, synthesised keyboard clicks and a door slam were not recognised and the siren onset was briefly labelled *Alarm*. Real recordings of those sounds are classified far more reliably than procedural synthesis.
- **CPU speed.** The AST classifier pads every 2 s window to its 10.24 s input; truncating positional embeddings was 7× faster but lost too much recall on short events, so accuracy was kept. Expect roughly 1.5× real-time on a laptop CPU, much faster on a GPU.
- **Forecasts are short-horizon and recording-local.** With ~24 intervals per file the AR(1) mostly learns mean reversion; it is a trend indicator, not a long-range predictor.
- **Spatial positions are a visualisation** for mono / stereo input — no direction-of-arrival estimation is performed.
- **The demo is synthetic.** The evaluation numbers measure the pipeline on clean TTS speech; real meetings with noise, accents and cross-talk will score lower.
- Single-user local application: no authentication, one analysis runs at a time.
